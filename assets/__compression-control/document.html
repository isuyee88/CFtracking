Compression Control Document

This file is intentionally text heavy so the CDN compression path can be tested against a direct static asset response without Worker mutation, without bootstrap injection, and without route-level application code.

Control Group

Served as a plain static asset from the asset pipeline to measure native edge behavior.

Header Check

Inspect content-encoding, etag, and cf-cache-status.

Body Check

Ensure the browser can parse the document normally and that compression does not corrupt bytes.

Compression experiments should separate the delivery path from the payload type. A document that is text only, cacheable, and stable gives a clean baseline for comparing direct assets, Worker proxying, manual precompressed variants, and runtime generated responses.

The production application already compresses JavaScript, CSS, bootstrap JSON, and SSE successfully. This page exists only to isolate why some document-like responses behave differently under the current Cloudflare configuration.

When testing, request this file with Accept-Encoding: zstd, br, gzip and compare it to the Worker demo routes under /__compression-demo/. The response size is large enough to make compression visible while staying small enough to inspect quickly during repeated debugging runs.
